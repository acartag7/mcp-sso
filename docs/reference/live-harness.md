# Live verification harness reference

`scripts/live/` contains the executable live verification tools. This page lists what each tool can establish. Current results belong in [Verification status](../verification-status.md) or [Client compatibility](../client-compatibility.md). Move a result to the [verification archive](../archive/verification-history.md) when a newer campaign supersedes it.

| File | Subject | Evidence |
| --- | --- | --- |
| `run.sh` | One named provider leg | Loads allowlisted values, validates the environment, identifies the runtime commit, and runs one probe. |
| `serve.sh` | One or more named provider legs | Starts the selected example servers, checks listener ownership, exposes the named tunnel, and supervises each child process. |
| `session.mjs` | A local manual-client session | `serve` runs `serve.sh` and marks the session ready after its first successful supervision check. `watch` reads the served legs' audit trails and records what each client flow reached. `cleanup` removes the helper's fixed `mcp-sso-live-<leg>` entries from Claude Code and Codex. A token exchange with no protected `/mcp` request is recorded as `TOKEN_ONLY`, not `PASS`. Results go to ignored working state under `.live-state/`; the helper does not turn them into release evidence or update documentation. |
| `probe-cloudflare.mjs` | Cloudflare Access | Checks that a provider-signed assertion reaches consent and that missing or attacker-signed assertions fail. |
| `probe-entra.mjs` | Microsoft Entra ID | Checks discovery, JWKS availability, the authorization redirect, the flow cookie, and one local group-denial control. |
| `probe-google.mjs` | Google | Checks discovery through the shipped OIDC discovery resolver, which requires HTTPS endpoints but is deliberately not the CIMD SSRF guard because the issuer is deployer-trusted configuration, and checks the authorization redirect to the validated endpoint. |
| `probe-e2e.mjs` | The shipped Fastify and SQLite example plus claims-only completion | Checks the selected DCR mode, authorization code flow, refresh rotation, replay-family revocation, revocation, an official MCP SDK call, the RFC 9728 challenge, Redis limiting, audit sequences, and credential non-publication. Its claims-only leg uses the same bridge dependencies and crosses Fastify, Express, and Hono. It checks verified claims, the host response, both `Set-Cookie` fields, the absence of consent and MCP tokens, `website-login:<ip>` keys, and the fixed redacted completion failure. It checks a replayed predecessor and confirms that the live successor is revoked. It then creates a second family and confirms that revocation affects that family. The stateless run checks an unknown opaque client without storing it. The machine-client checks run only in stored mode. |
| `drive-identity.mjs` | The real Cloudflare Access and Microsoft sign-in pages | Signs a provisioned Entra test user in headless through the machine's Chrome (or a CDP endpoint) and captures the Access assertion, or records where the account was denied: `denied_at_access_edge` (signed in, refused by the Access policy) or `denied_at_login` (refused by Microsoft). The password is typed only on `login.microsoftonline.com`; any other host ends the task before a keystroke. Prints one `outcome:` line, exits 0 only for a definite answer, and writes an owner-only result file with a page-class trace that `run.sh` reads as data; a result that is not an approved sign-in is refused there. |
| `probe-client.mjs` | A real OAuth client against a served leg on its public hostname | Registers a client, has the driver complete the authorization through the real provider pages as a provisioned test user, exchanges the code, calls a tool through the official MCP SDK, and refreshes once; or, for a deny fixture, checks that the client receives `access_denied` with the documented description and that the served leg's audit recorded `identity.verify` failed with exactly the expected reason and minted nothing. The audit trail is the authority, not the client's view. |
| `probe-cli.mjs` | Claude Code or Codex CLI against a served leg on its public hostname | Runs the real CLI's own login (`claude mcp login --no-browser` or `codex mcp add`) in a private `HOME` on a wide pseudo-terminal, checks that the authorization URL it prints is on the served origin and carries a client identity that CLI declares (Claude Code its published CIMD `client_id`; Codex either a per-instance CIMD document under its vendor's host or a dynamic registration, whichever it chose, with the served audit having to show that same path), has the driver complete it through the real provider pages as a provisioned test user onto the CLI's loopback callback, and checks the login's exit status, Claude Code's connection check on `/mcp`, and the served audit. A tool call runs when the client-keys file supplies the vendor key. |
| `rehearsal.mjs` | Every probe above, the driver, and both client probes against legs it serves itself, in order, through `run.sh` and `serve.sh` | Writes one receipt with the runtime commit, whether every row in the list ran (`complete`), and a `PASS`, `FAIL`, or `BLOCKED` status per row. The receipt keeps each row's `PASS`, `FAIL`, and `CONTROL` lines and its `NOTE` lines, which are what the row observed rather than what it checked: the client version a CLI row ran, the audit sequence, a skipped tool call. `record-receipt.mjs` reads them when it records the run. A `NOTE` is not a check, so a row that printed one and was then refused for an operator-armable reason is still `BLOCKED`. The `access-login` row must end `approved` and hands its assertion to `probe-cloudflare`; the `access-edge-denial` row must end `denied_at_access_edge` (checklist E1), and a denial at the Microsoft login fails it. The client rows run inside serve generations the rehearsal starts and stops itself, on every exit path including a signal; a generation whose public hostname already answers is refused as `tunnel_already_served`. A row is `BLOCKED` only for an operator-armable reason that stopped it before its checks ran (`cloudflare_access_login_required`, `google_credentials_absent`, `infrastructure_session_expired`, `browser_unavailable`, `cli_unavailable`, `browser_not_local`, `blocked_mfa_interstitial`, `release_services_absent`, `tunnel_already_served`, `tunnel_credentials_absent`, `cloudflared_unavailable`, `prerequisite_row_did_not_pass`); any other refusal, failed check, zero checks, a driver exit status that disagrees with its outcome, an unexpected sign-in outcome, or a generation that dies or never answers (`serve_failed`) is `FAIL`. Exits 0 only when every row in the list ran and passed on a clean tree; a `--rows` subset is `complete: false` and never evidence. A row whose output contains a configured private value, or an assertion the driver captured, is failed as `private_value_in_output` and its lines are withheld; the serialized receipt is scanned again before it is written. |
| `record-receipt.mjs` | A passing receipt | Turns it into the release evidence `check:release-ready` reads: one JSON document under `docs/evidence/` naming the runtime commit, every row and its status, and the release-matrix rows the run proved. Completeness is re-derived from the receipt's own rows rather than trusted, so a partial run, a dirty tree, a failed row, or a row the rehearsal does not define writes nothing. Nothing renders prose: `docs/client-compatibility.md` is written for readers. |
| `ci/` | The same rehearsal on a GitHub-hosted runner (`.github/workflows/live.yml`) | `fetch-bundle.mjs` reads the `/mcp-sso/live/*` secrets through the OIDC-assumed role into 0600 files, `mask-bundle.mjs` registers every private value with the log masker (every value under a credential or identity key, every other string of 12 characters or more, each line of a multi-line value, and the bare hostname of any URL), and `ci/infra/scripts/tofu-run.sh` answers `run.sh`'s stack-output calls from the bundle so `run.sh` runs unchanged. The workflow runs nightly and on demand from `main` under the `live` environment, and on `rehearsal/*` pushes under the `live-branch` environment, whose required reviewer approves each run before the role is assumed; its first step refuses any other ref, and it never runs on pull requests. |
| `CHECKLIST.md` | Live MCP clients | Lists the client and identity-provider combinations, which of them the rehearsal drives, and which an operator must still run. |

## What the connector can reach

`serve.sh` starts `cloudflared` without the variables that name the run's private files: `MCP_SSO_BUNDLE_DIR`, `MCP_SSO_GOOGLE_ENV`, and `MCP_SSO_CLIENT_KEYS_FILE` are removed from its environment, so the connector is not told where the CI bundle, the Google credential file, or the vendor keys are. It still runs as the user that owns them, and their paths are not secret, so this removes a pointer rather than an ability: the 0600 modes are what actually stands between the connector and those files. Real isolation would run the connector under its own operating-system identity, or in a container with only its tunnel credential mounted, which is not what this harness does today. The connector is pinned to one release asset and verified by SHA-256 before it runs, which is the assumption the current shape rests on.

## Evidence boundary

A harness run is not provider evidence unless it reaches the named provider infrastructure and records the observed result. A unit or integration test can prove that the harness routes inputs correctly. It cannot prove that a provider accepted a request.

`session.mjs watch` derives its result from `.live-state/<leg>/audit.jsonl`, not from a client message. It accepts only a session that reached the ready marker and ignores events older than that session's start, so a failed start cannot relabel the previous run with a new commit. A complete authorization-code exchange with at least one later successful protected request is `PASS`. A complete exchange without a protected request is `TOKEN_ONLY`. A failed identity event is `DENIED`, and a flow that reaches neither result is `INCOMPLETE`. An identity failure with no client id becomes its own unattributed denial instead of changing the preceding client's result. An unreadable JSON line makes the watch command fail and records no result for that trail.

Codex can use an opaque dynamic-registration id when it is signed out of its vendor account. For that run, the operator adds `--codex-dcr` to `watch`. The flag attributes only a loopback flow whose client id has Codex's generated `mcpdc_` shape. Without the flag, the same flow remains an unassigned local CLI observation and does not fill B1 through B3.

`session.mjs serve` accepts only the three named legs and rejects repeats before starting `serve.sh`. It first writes an invalid `starting` record. `serve.sh` sends the ready marker only after the tunnel and every selected server survive one supervision interval, then the wrapper makes the session usable by `watch`. A startup failure removes the record when possible, and a leftover `starting` record is still rejected. The helper reserves `mcp-sso-live-cloudflare_access`, `mcp-sso-live-entra`, and `mcp-sso-live-google` as its Claude Code and Codex entry names. Normal serve shutdown attempts every selected cleanup target. `session.mjs cleanup` attempts all six targets after a crash. A missing entry is already clean. Any other client-command failure makes cleanup fail after it has attempted the remaining targets. No cleanup path reads a name from a file or accepts one from the command line, so it cannot select another MCP entry.

The helper treats the audit and session files as untrusted local input. Reads do not follow a final symlink and reject non-files, oversized files, malformed rows, unknown events, and wrong field types. Result and session writes require a private `.live-state/` directory and a private single-link regular file. The helper is repository tooling; the npm package allowlist does not include `session.mjs` or `scripts/`.

Two rules keep a run reproducible. The provider mapping and credentials reach the process through configuration and `run.sh`, never by patching source: a run that edits library or example code to make a leg pass has verified the patch, not the release, and is not evidence. Provider credentials and private infrastructure handles arrive through `MCP_SSO_*` environment variables for the duration of the run, and every probe's output guards keep them out of the evidence it prints. Everything a run observes, such as reason codes, statuses, and flows, is public and belongs in the current results pages.

`probe-e2e.mjs` proves that the selected `MCP_SSO_DCR_MODE` reached the built app by its outcome for an unknown opaque client after registration: stored mode refuses it with `401 invalid_client`; stateless mode admits it against the global redirect allowlist and returns a consent token. A probe run whose outcome does not match the selected mode has failed, whatever the preflight variable says.

Each probe uses a disposable state directory and closes the app, store, and directory on every exit path. Each probe validates the effective redirect allowlist before provider I/O. A probe reports `FAIL` when it cannot exercise a required check. none reports `SKIP`.

`run.sh` refuses a checkout with tracked changes unless `MCP_SSO_ALLOW_DIRTY=true` marks the run as non-evidence. It disables inherited shell tracing before it handles secrets and passes an allowlisted environment to the probe.

`serve.sh` uses `MCP_SSO_READINESS_SECONDS`, with a default of 60 seconds, as the readiness deadline. It accepts readiness only when the child it started is the sole listener on the configured port. It checks listener ownership again before exposing the tunnel.
